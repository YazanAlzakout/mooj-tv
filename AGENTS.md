# Mooj TV — what this project already knows

This app was cloned from a sibling player that had been through two years of
production. Most of what follows was learned there, expensively, and is
written down so it does not have to be learned twice.

Read it before changing anything.

---

## The brand lives in one file

`brand.config.js` at the root. `app.config.js` reads it for build identity;
`src/core/brand/index.ts` reads the runtime half out of `extra.brand`, with
literal fallbacks because `Constants.expoConfig` can come back null and an
undefined database name opens the wrong file.

Run **`node tools/verify-brand.js`** before any release build. It proves the
fallbacks still match, that the signing properties carry this brand's prefix,
and that no file names the brand this was cloned from.

Standing up a further brand: copy `brand.config.js`, change the values,
replace `assets/images/`, update the three literals in
`src/core/brand/index.ts`. The verifier catches a half-done job.

## Signing

Gradle properties `MOOJ_UPLOAD_STORE_FILE`, `..._STORE_PASSWORD`,
`..._KEY_ALIAS`, `..._KEY_PASSWORD`, defined in `~/.gradle/gradle.properties`
— outside the project, because `android/gradle.properties` is regenerated by
prebuild.

**The prefix is brand-specific and that is not cosmetic.** This machine holds
another app's upload properties in the same file, and
`plugins/withReleaseSigning.js` activates on a property merely being present.
A shared prefix signs this app with the other one's key, silently, with no
error, until the Play upload — or never.

A release build with the properties absent falls back to the **debug** key
rather than failing. Verify what you actually built:

    apksigner verify --print-certs <apk>      # APKs are v2/v3-signed only
    keytool -printcert -jarfile <aab>         # AABs carry a JAR signature

A debug-signed artifact shows `CN=Android Debug`.

## Version numbers

`VERSION_CODE_BASE` in `app.config.js`, raised by hand. Nothing increments it.

**Read a free number from App bundle explorer in Play Console — never infer
one from the repository.** In the sibling project a code looked unused because
no commit mentioned it; Play refused the upload, because a build had reached a
test track and left no trace in git. Git knows what was *built*, not what was
*uploaded*.

Play needs an **AAB** (`bundleRelease`). An APK (`assembleRelease`) is for
sideloading onto a test device.

## Never EAS Build

Builds are native and local. The EAS project id was removed deliberately.

    cd /d D:\Projects\mooj-tv && android\gradlew.bat -p android bundleRelease

## The provider panel

- **No per-item request bursts.** The panel answers empty-bodied 404s on
  every endpoint once the request *rate* crosses its limit, and it stays that
  way for a while. Fan-out of one request per card or per row is the thing
  that triggers it. This is a rule about request rate, not about how many
  streams are open.
- **Each customer has three stream connections**, not one. Read
  `session.accountInfo.maxConnections`; never assume.
- **Credentials live only in SecureStore.** Never in SQLite, never in a log
  line, never rendered. A stream URL carries the username and the password.

## Never name the content source in the interface

Nothing on screen may say that a shortcut exists, or what any code points at.
`src/providers/serverShortcodes.ts` maps a number to a server so a remote's
number keys can replace an on-screen keyboard, and `add-provider.tsx`
deliberately shows a neutral label rather than the address — a server address
printed as a provider's name undoes the masking everywhere else.

The reason is not technical. A developer who is also visibly the source of the
content is a different kind of listing with different rules.

## House style

- No emoji anywhere in the interface.
- Comments say *why*, and name the date and the symptom when they record a
  fix. The comment density here is deliberate; match it.
- `memo(function Name() {})` — `react/display-name` rejects an arrow.
- Hooks sit above early returns, always.
- React Compiler lint rules are **errors**, not warnings. Anything a hook
  captures is treated as frozen.
- Reanimated 4 springs take `{duration, dampingRatio, clamp}` **or**
  `{stiffness, damping}`. `restDisplacementThreshold` and `restSpeedThreshold`
  are version 2 and 3 keys: version 4 ignores them in silence, and TypeScript
  does not catch it through an `as const`.
- A function declared inside a worklet is itself workletized. Building a
  worklet inside a worklet every frame fails without saying so.

## Expo has changed

Read the exact versioned documentation at
<https://docs.expo.dev/versions/v57.0.0/> before writing code against an Expo
API. Do not reach for what the API used to be.

## Known, open, deliberate

- **The update notice does not reliably appear.** `src/app/index.tsx` fires
  the Play check without awaiting it, then `router.replace("/home")` unmounts
  the screen the notice would render on, so the result usually arrives after
  the only thing that could show it is gone. Inherited from the sibling app,
  where it is live. Fixing it means moving the notice somewhere the startup
  gate does not navigate away from.
- **R8 is off** (`minifyEnabled false`), so Play reports the DEX optimisation
  score at its floor. Turning it on needs `keep` rules for every native module
  and a real device test: the failures appear only in release builds.
